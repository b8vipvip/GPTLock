从安装到日常聊天

先看路线，再做步骤。

GPTLock 的核心不是“每次聊天都验证一次”，而是把一次性的安装与策略配置做好。之后正常聊天；只有需要诊断或确认时才使用自动验证和运行日志。

01

安装 GPTLock

Windows 使用正式发布的 GPTLockSetup-x64.exe；Linux 使用对应的 deb。安装后在 Chrome / Edge 的扩展管理页开启开发者模式，加载安装目录里的 extension，并完全重启浏览器。

Windows: %LOCALAPPDATA%\GPTLock\extensionLinux: /usr/share/gptlock/extension
02

确认 Native Core 在线

打开 GPTLock 设置。Core 在线代表扩展已经能与本地可信执行组件通信；如果离线，先修复安装或 Native Messaging，不要继续猜模型状态。

Core Connected固定扩展 ID
03

登录 GPTLock 账户

在插件中登录账户。账户决定权益与设备绑定；网站的账户中心可查看当前权益、释放旧设备、注销插件会话和修改密码。

04

选择模型与推理强度

在设置中选择允许模型、首选模型以及允许的推理强度。GPTLock 只改写它能安全识别的正式请求字段，不会凭空制造网页没有发送的推理字段。

允许模型首选模型Low / Medium / High / Extra-high
05

开启锁定，然后正常聊天

开启 GPTLock 后直接回到 chatgpt.com 输入消息并发送。请求锁定是主功能，不要求先完成一次“验证成功”才能聊天。

06

理解“锁定”和“确认”的区别

请求锁定说明网页向服务端发出了符合策略的模型请求；响应确认只在 ChatGPT 向浏览器暴露可解析元数据时成立。后端仍可能受账号权限、额度和产品路由影响。

locked ≠ backend guaranteeverified = browser-visible evidenceunverified 不等于失败
07

遇到异常再用自动验证

“自动验证”会尽力对齐页面状态、自动写入测试消息并发送，再捕获该轮请求与响应证据。出现问题时导出诊断包或运行日志，比反复手动试更有价值。

08

保持更新

Windows 新版支持一键自动更新。设置里的“打开发布页”会回到本站；版本发布页同时保留 GitHub 正式 Release 的安装包和校验信息。
